워크플로우 만들기
ComfyUI에서 워크플로우를 만들어 export하지 않아도, 설치된 모델로 표준 파이프라인(체크포인트 → LoRA → 프롬프트 → KSampler → 저장)을 여기서 바로 조립할 수 있어요. 만든 워크플로우는 업로드한 파일과 똑같이 "작업 관리" 탭에서 큐에 넣습니다.
만들어진 워크플로우 JSON
베이스 모델 (Family)
체크포인트를 "wai-illustrious", "krea.2"처럼 서로 호환되는 계열(family)로 묶어두면, "새 작업 추가" 마법사가 이 family를 기준으로 워크플로우 유형/LoRA/ControlNet 프리셋을 걸러서 보여줘요. family 하나에 체크포인트를 여러 개(같은 계열의 다른 파인튜닝 등) 넣을 수 있어요.
LoRA 트리거 워드 / 호환 베이스 모델
ComfyUI에 설치된 LoRA마다 트리거 워드(그 LoRA를 쓰려면 프롬프트에 넣어야 하는 단어/문구 — civitai 등 배포처에 적혀 있는 값)를 입력해두면, "🧩 워크플로우" 탭과 "새 작업 추가" 마법사에서 그 LoRA를 고를 때 긍정 프롬프트에 자동으로 덧붙어요. 호환 베이스 모델을 하나도 안 고르면 모든 베이스 모델과 호환되는 것으로 취급돼요 (마법사에서 항상 보임) — 특정 family에서만 써야 하는 LoRA라면 체크해두세요. 입력/체크하면 바로 저장돼요.
ControlNet 프리셋 워크플로우
OpenPose/Depth/Lineart ControlNet 워크플로우 유형은 체크포인트마다 ControlNet 로더/가중치 배선이 달라서 자동으로 조립할 수 없어요 — family별로 미리 만들어둔 워크플로우 JSON을 여기 올려두면, "새 작업 추가" 마법사가 그 family를 고를 때 그대로 재사용해요(family에 프리셋이 없는 유형은 마법사에서 안 보여요).

API 키
서버에 NIGHTSHIFT_API_KEY가 설정돼 있으면, 이 브라우저가 API를 호출할 때마다 같은 값을 보내야 해요. 여기 입력하면 이 브라우저의 localStorage에만 저장되고, 이후 요청에 X-API-Key 헤더로만 실려요. 서버에 키를 설정하지 않았다면 비워둬도 돼요.
➕ 파드 추가
파드는 nightshift가 작업을 보낼 워커예요. 종류(kind)가 그 워커를 어떻게 다룰지 정합니다. 주소를 비워두면 COMFY_URL 환경변수 → 127.0.0.1 자동 탐지 순으로 찾아요.
이 파드에서 한 번에 몇 개까지 돌릴지. GPU 한 장이면 1이 보통이에요.
끄면 새 작업을 보낼 수 없어요(기록은 남습니다). 파드를 잠시 쉬게 할 때 씁니다.
다른 파드로 옮기기
파드마다 큐가 따로 돌아서, 파드 하나가 멈추면 그 큐만 멈춰요. 아직 시작하지 않은 작업은 다른 파드로 옮겨 이어서 돌릴 수 있어요(실행 중인 작업은 먼저 멈춰야 해요).
ComfyUI 접속 주소
nightshift가 작업을 보낼 ComfyUI 서버 주소예요. 같은 머신에서 돌고 있으면 비워둬도 자동으로 찾지만, ComfyUI만 다른 곳(예: 원격 GPU pod)에서 돌고 있다면 그 주소를 여기 넣으세요. 저장하면 서버를 재시작하지 않아도 바로 반영됩니다 — pod를 새로 만들어 주소가 바뀌었을 때 여기만 갈아끼우면 돼요.
ComfyUI가 원격에 있으면 결과 이미지도 그쪽 디스크에만 쌓여서 갤러리가 비어 보여요. 켜두면 작업이 끝날 때마다 그 작업의 이미지를 이 서버의 출력 폴더로 자동으로 받아옵니다 (한 번 받아온 이미지는 갤러리에서 지워도 다시 받지 않아요). ComfyUI가 같은 머신에서 돌고 있다면 켤 필요 없어요.
